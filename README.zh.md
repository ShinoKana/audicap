# Audicap

Audicap 是一个免费、开源（MIT）的 macOS 菜单栏应用，给 Mac 正在播放的任何声音——Zoom、Google Meet、Teams、YouTube，或者其他任何 app——做实时字幕，识别完全在本机完成（用苹果的 `SpeechAnalyzer`），支持多语言会议里逐句自动切换识别语言。需要 macOS 26 及以上、Apple Silicon。

- **是什么**：一个菜单栏应用，抓取 Mac 的系统声音并显示实时字幕浮窗，识别在本机完成，逐句自动判断语言。
- **适合谁**：会议或视频里混杂多种语言（比如日语/英语/中文）、或口音较重，又不想让机器人加入会议的人。
- **系统要求**：macOS 26 及以上，Apple Silicon。

[English](README.md)

Audicap 直接抓取系统声音（不用装虚拟声卡，也不会有机器人加入会议），文字显示在一个透明浮窗里，其他参会者看不到任何东西。每场会议都会留下记录和录音，散会后可以选择整理成带说话人标注的完整稿。

## 适合谁用

如果你开会经常混用多种语言——比如同一场会里日语、英语、中文来回切换，或者口音比较重——又不想让一个机器人加入会议，Audicap 是为这个场景做的。

如果你的会议从头到尾只用一种语言，有两个更成熟的选择：macOS 自带的实时字幕，或者 [livesub-macos (JaSub)](https://github.com/ultima6-tw/livesub-macos)——后者的翻译做得也更精细。如果你真正要的是云端会议记录或摘要，而不是实时字幕，Otter 或 Granola 是另一类工具，不是同一类东西，具体差异见下面的对比表。

## 安装（直接下载）

1. 从 [GitHub Releases 页面](../../releases) 下载 zip，解压后把 `Audicap.app` 拖进 `/Applications`。
2. **第一次打开时**：这个构建没有做 Apple 公证，macOS 会直接拦下来。可以右键点 app 选“打开”，或者去系统设置 → 隐私与安全性 → 点“仍要打开”。也可以自己去掉隔离标记：
   ```sh
   xattr -dr com.apple.quarantine /Applications/Audicap.app
   ```
3. 弹窗要求时授予“屏幕录制”权限（开了麦克风的话再给“麦克风”权限）。授权之后要退出重开一次——macOS 是在下次启动时才真正生效，不是当场生效。菜单栏图标的菜单会显示当前权限状态，也有一项“检查权限…”可以直接跳回系统设置。
   另外提醒一下：这个构建用的是 ad-hoc 签名（没有付费的 Apple 开发者证书），每次发布签名身份都会变。**更新之后如果字幕一直是空的**：打开“系统设置 → 隐私与安全性 → 屏幕录制”，删掉旧的 Audicap 条目，重新打开 Audicap 并授权，然后再退出、重开一次（macOS 要重启 app 才会生效）。
4. **系统要求**：macOS 26 及以上，Apple Silicon。目前只测过这一种配置，Intel Mac 没测过。

**录音需要对方同意**：Audicap 会把它抓到的声音都转成文字，包括通话里其他人说的话。如果所在地法律要求录音/转写前要取得对方同意，这件事由你自己负责。

**License**：MIT。

## 支持的语言

11 种可选语言：日语、英语、普通话（简体）、普通话（繁体）、粤语、韩语、法语、德语、西班牙语、意大利语、葡萄牙语。

可以只选一种，也可以在自动模式里选最多 5 种同时跑——这是苹果的限制，每个 app 最多同时占用 5 个语言模型（`AssetInventory.maximumReservedLocales`）。自动模式下，每种选中的语言各跑一路独立识别，然后按置信度逐句挑出最好的结果（见下面“功能”）。默认的自动模式组合是日语 + 英语 + 普通话（简体）。

**测试情况**：日语、英语、普通话（简体）已经在真实会议里用过。另外 8 种语言目前只用合成语音测试过——在这些测试里它们能正确识别，也没有把 ja/en/zh 三路的结果抢走，但还没有在真实会议里验证过。口音较重的语音是语言判断最容易出错的情况（见下面“限制”）；如果一场会从头到尾只说英语，建议直接选英语，不要用自动模式。

## 功能

- **系统声音实时字幕**：无边框浮窗，可以拖动。默认最多显示 4 行，自动折行和译文都算行数。
- **每句判断语言**：每种语言的识别都会给自己的结果打分，按置信度选出胜者。如果某一路给出的文字系统不对（假名 / 汉字 / 谚文 / 拉丁字母），就扣分。如果最好的结果把握也不大（< 0.80），而且还有别的路没给结果，就最多再等 2 秒：实测有一路判断“一句话结束”的时间比其他路早 1.8 秒左右。
- **本机翻译**（苹果的 Translation 框架）：译文用另一种颜色的小字显示在原文下面，复制时不会带上。
- **会中云端纠错（可选）**：按句子边界把识别结果攒成 4–20 秒一段，连同这段音频发给 `gemini-2.5-flash-lite`（经 OpenRouter），约 $0.01/小时。只有这一段里每句都判成同一种语言、且置信度都 ≥ 0.85 时，才告诉模型是什么语言；否则让它按实际听到的写。
- **麦克风（可选）**：你自己说的话只进记录，不上字幕。固定使用内置麦克风，这样蓝牙耳机不会被切换到通话模式、音质也不会变差。
- **记录面板**：记录会边说边更新；选中即复制，复制时自动去掉时间戳。
- **每场会议生成三个文件**：`.txt` 是原始识别结果，只追加、不改动；`.md` 是最终稿，被纠错改过的行标 ✎；`.wav` 是 16kHz 单声道录音。
- **散会后整理（可选）**：录音超过 5 分钟时，停止转写后会弹窗问你要不要运行外部脚本，生成完整稿和说话人标注。脚本不在本仓库，见下面“限制”。
- **菜单栏状态菜单**：显示当前状态、屏幕录制和麦克风的权限情况、一项“检查权限…”和一项“显示日志文件”。
- 全局快捷键 `⌥⌘A`：开始 / 停止。

## 常见问题

**有没有免费的 Mac 软件，能给 Zoom 做实时字幕，又不用机器人进会议？**
有，Audicap 就是。它用 ScreenCaptureKit 抓系统声音，任何 app 都能用，不会有机器人作为参会者加进来。

**会上在日语、英语、中文之间来回切换，能跟得上吗？**
能。自动模式下，你选的每种语言各跑一路识别，同时进行（最多 5 路，这是苹果的限制），每一句按置信度挑出最好的结果，所以开会时在几种语言之间切换不用改设置。

**能离线用吗？录音会离开我的电脑吗？**
默认不会，识别和翻译都在本机完成。只有两个可选功能会把音频发到云端：会中纠错（经 OpenRouter 调用 Gemini），以及散会后生成完整稿；散会后那一步每次都会先弹窗问你。

**能在 Windows、Linux 或 iPhone 上用吗？**
都不能。抓声音用的 ScreenCaptureKit 和识别用的 `SpeechAnalyzer`（macOS 26）都是苹果桌面系统专有的接口。也做不成 iPhone app：iOS 不允许一个 app 抓取其他 app 的声音，而这正是 Audicap 的工作原理所依赖的。

## 限制

- **只支持 macOS 26 及以上。** `SpeechAnalyzer` 是 macOS 26 才有的。
- **最多同时 5 种语言。** 苹果规定每个 app 最多占用 5 个语言模型（`AssetInventory.maximumReservedLocales`）。换选择时，Audicap 会把不用的释放掉。刚切换完的几秒，模型还在加载，这段可能识别不到。
- **语言开得越多，越容易选错。** 口音英语最难：测试中，用日语声音读的英语，英语路只得到 0.18，结果被日语路抢走。如果某场会基本只说英语，就只选英语。
- 抓取期间，菜单栏会一直显示紫色的“屏幕共享”指示器，这是 ScreenCaptureKit 的要求。改用 Core Audio tap 可以不出这个指示器，但在 macOS 26.4 上会导致播放出现爆音。
- `.wav` 里只有系统声音；麦克风那一路只做识别，不录音。
- 记录存放位置在“设置 → 记录”里选，默认 `~/Documents/Audicap`。散会后整理用的是外部脚本（默认 `~/whisper-job/_pipeline/audicap_post.sh`，存放位置通过环境变量 `AUDICAP_DIR` 传给它），脚本不存在时这个功能会自动跳过。

## 故障排查

- **字幕一直是空的**：打开菜单栏菜单，看屏幕录制 / 麦克风的权限状态。没授权的话，用“检查权限…”跳到系统设置，授予屏幕录制（用了麦克风的话也授予麦克风权限），然后退出重开 Audicap。
- **更新到新版本之后**：因为每个发布版都是 ad-hoc 签名、签名身份不一样，之前给过的权限可能失效。去“系统设置 → 隐私与安全性 → 屏幕录制”删掉旧的 Audicap 条目，重新打开 Audicap 再授权一次。
- **权限弹窗反复弹出**：Audicap 一旦判断权限没给，就不会再自动重试抓取（重试也只会一直重新弹窗，不会成功，因为 macOS 只在重启 app 后才真正应用权限变化）。授权后把 app 关掉重开就行。
- **日志**：菜单里有“显示日志文件”一项。日志写在 `~/Library/Logs/Audicap/audicap.log`。

## 从源码构建

需要 macOS 26 和 Xcode Command Line Tools（SDK 26 或以上）。

1. **创建一个自签名的代码签名证书，名字叫 `AudicapDev`**：钥匙串访问 → 证书助理 → 创建证书，类型选“代码签名”。macOS 的“屏幕录制”授权是跟着签名身份走的；如果用临时签名（ad-hoc），每次重新编译都会被当成一个新 app，得重新授权。
2. 在你自己的终端里运行：
   ```sh
   ./deploy.sh
   ```
   脚本会先在临时目录里编译、签名、校验，全部通过后才装到 `~/Applications/Audicap.app`，上一版会保留为 `Audicap.app.prev`。`codesign` 需要访问钥匙串，第一次运行时点“始终允许”。
3. 第一次启动时，授予“屏幕录制”权限；如果开了麦克风，再授予“麦克风”权限。
4. 云端纠错（可选）：在设置里填入 OpenRouter 的 API key。key 存在本机的 UserDefaults 里，不在代码中。

如果想自己打一个可以分发的 zip，而不是装到本机，用 `./release.sh <版本号>`（比如 `./release.sh 0.1.0`）——它用 ad-hoc 签名，不需要访问钥匙串，打出来的 zip 在 `build/` 目录下。

## 设计取舍

下面每一条都来自实测，细节写在代码注释里。

- **实时识别用 SpeechAnalyzer，不用 Whisper。** 同样的素材，SpeechAnalyzer 流式速度是实时的 60–97 倍，whisper large-v3-turbo 约 3 倍；内存只多约 8MB，而 whisper 要 1.5GB。短应答（「はい」、“Yes”）几乎不漏，静音时也不会编出内容。能看到完整上下文的整段转写更准，所以完整稿放到散会后再做。
- **云端纠错要发音频，不能只发文字。** 只看文字的话，模型听不到说话的人，常常把本来对的词“改”错。
- **发音频时不附带识别文字。** 附上之后，模型会先把那段文字复述一遍，再接上自己的转写，结果每句话都出现两次。
- **按句子边界切，不按固定秒数切。** 识别器给出最终结果的位置正好是说话的停顿；按固定长度切会把词切断。
